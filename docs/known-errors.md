# Известные ошибки и восстановление YAPLIX

Справочник действий по текущему коду. Реальные результаты и ограничения сети
TASK-008 зафиксированы в [отчёте](task-008-report.md); они не доказывают причину
каждого будущего сбоя. Сначала сохраните запрос/черновик и проверьте этап,
код ошибки, состояние задания и диагностику. Не прикладывайте `.env`, ключи,
initData или необработанные журналы. [Запуск и обслуживание](../README.md).

| Ошибка / симптом | Причина и безопасное действие |
| --- | --- |
| `PORT_IN_USE` | Launcher не подтвердил совместимый local backend этого клона. Windows: `Get-NetTCPConnection -LocalPort 3000`, затем `Get-Process -Id PID`. Не останавливайте неизвестный процесс. Свой устаревший backend перезапустите; либо явно выберите другой `PORT`. Doctor проверяет новый bind и может сообщить эту ошибку при здоровом активном сервере. |
| `TUNNEL_CLOSED` / `SPAWN_ERROR` | Просмотрите этап, exit code/signal и фильтрованный `.local/logs/tunnel.log`. Нужен pinned cloudflared из `npm run tunnel:install`; проверьте права запуска/карантин. Не отключайте TLS, антивирус или firewall. Предыдущая ошибка без stderr не устанавливает корневую причину. |
| `PUBLIC_URL_TIMEOUT` / `PUBLIC_HEALTH_FAILED` | URL ожидается до 60 s, внешний HTTPS health до 45 s. Полученный hostname сам по себе не означает доступность. Проверьте DNS/VPN/proxy и исходящие HTTPS 443, QUIC UDP 7844 или HTTP/2 TCP 7844; повторите с явным `--protocol http2` либо `quic`. При неподтверждённом health меню не публикуется. TASK-008 наблюдал DNS ENOTFOUND/timeout; конкретный сетевой виновник не установлен. |
| `LLM_OUTPUT_TRUNCATED` | Провайдер вернул `finish_reason=length`. Задание сохраняет полученный код/model; bounded repair просит компактный полный HTML. Если исправление не получилось, скачайте черновик и выберите «Продолжить генерацию». Не увеличивайте `LLM_MAX_TOKENS` вслепую: учитывайте model metadata и output/reasoning usage, если доступны. |
| `LLM_CONTEXT_LIMIT` | Контекст превышает ограничение модели. Запрос и доступный checkpoint остаются; проверьте подходящую модель и настройки перед ручным продолжением. Автоматическая смена модели для обхода этого отказа не выполняется. |
| `LLM_RATE_LIMIT` / `JOB_RETRY_AFTER` | Provider `429`: сохраняется Retry-After, если получен. Подождите указанное время; продолжение до него блокируется. Автоматических повторов и скрытого перехода к резерву для этого отказа нет. |
| `LLM_QUOTA` | Provider `402` или quota error в stream. Проверьте квоту аккаунта. Задание остаётся с запросом и черновиком; повтор только по явному действию после устранения причины. Платная OpenRouter модель не используется вместо `openrouter/free`. |
| `LLM_AUTH` / `LLM_MODEL_NOT_FOUND` / `OLLAMA_CLOUD_NOT_CONFIGURED` | Проверьте локальные server KEY и exact MODEL, затем перезапустите backend. Ollama Cloud использует отдельные `OLLAMA_CLOUD_API_KEY/MODEL`; cloud ID берётся из официального API, не из догадки о суффиксе local CLI. «Модель доступна» не означает успешную генерацию. |
| `LLM_TIMEOUT` / `LLM_CONNECTION_INTERRUPTED` / `LLM_STREAM_ERROR` | Deadline или обрыв потока оставляет исходный запрос и последний записанный checkpoint, если код поступал. Скачайте черновик; продолжайте явно после восстановления связи. Последние ещё не записанные байты могут отсутствовать. Не гарантируется буквальное продолжение с последнего токена. |
| `LLM_INVALID_RESPONSE` / `LLM_INVALID_HTML` / `LLM_UNSAFE_ARTIFACT` / `BROWSER_*` | Неполный документ или отказ проверки не создаёт игровую версию. Bounded repair использует исходные требования и полезный код; дальше «Нужно действие». Для `BROWSER_INSTALL_REQUIRED` выполните `npm run checker:install`. При sandbox error устраните поддержку sandbox ОС по [setup](development-setup.md); не выключайте его. |
| `JOB_RESTART_UNCERTAIN` | Запрос уже мог быть принят провайдером до restart. Автоматический повтор остановлен; запрос, metadata и записанный черновик остаются. «Продолжить генерацию» может сделать новый вызов, используя сохранённый контекст. Queued-задания ещё не отправлялись и могут стартовать после запуска backend. |
| `JOB_QUEUE_FULL` / `RATE_LIMIT` | Один worker, до 20 pending глобально и 3 на владельца при creation/continue. LIVE creation при настроенном generator: 6/min owner, 12/min global. Отдельно такие же лимиты фактических provider dispatch, включая repair/Continue. Подождите завершения/отмените своё ненужное задание. Cancel не удаляет запрос и checkpoint. |
| `JOB_WORKER_BUSY` | После successful bind lease защищает одну DB от второго backend, в том числе на другом порте. Закройте только свой writer штатно. После crash подтверждённо отсутствующий PID позволяет restart сразу; живой/непроверяемый PID сохраняет lease до 60 s. Чужой процесс/lease не удаляйте, игры и записанные checkpoints сохраните. |
| `JOB_ATTEMPT_LIMIT` / `JOB_STORAGE_QUOTA` | До 6 вызовов за запуск, 12 за задание, до 1000 заданий, 100 MB checkpoints суммарно и 200000 bytes на checkpoint. Повторы/хранилище ограничены. Сохраните backup и скачайте черновик; автоматического удаления заданий/увеличения квот нет. |
| `IDEMPOTENCY_CONFLICT` | Один key был использован с разными запросами. Не повторяйте изменённое тело со старым key; существующее задание сохранено. UI защищает повторное нажатие и повтор того же незавершённого submit. |
| Уведомление скрыто/не доставлено | Результат остаётся в центре заданий и библиотеке. Toast имеет серверный claim перед показом; crash может оставить только центр. Telegram требует явное согласие, signed session, HTTPS и доступ бота к чату. Одна попытка отправки, timeout может быть unknown; гарантии exactly-once доставки нет, повторного спама нет. |
| `SCHEMA_INVALID` / `SCHEMA_TOO_NEW` / `BACKUP_*` | Не пересоздавайте и не удаляйте базу. Остановите свой writer, сохраните DB/WAL/SHM и protective `before-v2-*` snapshots. Неизвестная схема/неисправная копия блокируют запуск. Restore выполняйте только из проверенной копии по [setup](development-setup.md). |

Обычный browser и synthetic fixtures не подтверждают physical Android/iOS,
реальный Telegram API/menu/доставку сообщений или успешный Ollama Cloud inference.
При недоступности всех настроенных вычислений задание может остаться черновиком;
оно не становится DEMO и не получает отметку passed без проверки полного HTML.
