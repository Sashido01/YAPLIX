пользователей. Дата фиксации: 2026-10-17. Бюджет реального LLM inference POST: **0**.
Генератор и существующие тесты не изменены. Результаты понимания языка и генерации

## Файлы и назначение

- [DEV](dev-prompts.json): 5 игровых запросов для будущей разработки и настройки.
- [HELD-OUT](held-out-prompts.json): 3 контрольных запроса, 3 жанра, только итоговое сравнение.
- [Корпус](intent-corpus.json): 40 фраз для разбора намерений, включая невалидный ввод.
- [Проверка](validate.py): автономная проверка целостности без зависимостей и сети.

Текст `text` сохраняется дословно, включая ошибки, сленг, пустую строку и пробелы.
Аннотации отделены от него; их нельзя подставлять в пользовательский запрос.
DEV/HELD-OUT содержат жанр, аудиторию, основные механики, явные требования и
наблюдаемые критерии. Неявные традиционные механики именованных игр — ожидания
автора теста, а не буквальные пользовательские требования. Критерии служат для
будущей ручной проверки; NL-000 не запускает игры из этих запросов.

## Разметка intent-corpus

Каждая запись: id, точный text, tags, expected, notes. Каждый признак expected
содержит value, source, evidence:

- EXPLICIT: значение прямо выражено текстом (допускается нормализация синонимов).
- INFERRED: уверенный вывод из названия игры или описания действия; основание записано.
- DEFAULT: явно обозначенная политика продукта, а не извлечённое пожелание.
  Здесь только platform_controls из текущего UI; даже у невалидного ввода это
  справочная политика, **не разрешение на генерацию**.
- UNKNOWN: недостаточно данных; value и evidence равны null. Не ставить default
  вместо отсутствующих сведений об аудитории или цели. Неизвестный список не равен [].

Признаки: genre, audience, mechanics, numeric_conditions, input_status,
platform_controls. Значения жанров и механик — словарь теста, не новая схема API.
`default` в audience означает явно универсальную аудиторию. «Бабушка», «мама»,
«взрослые», «подростки», возраст автора и опыт сами по себе не переводятся в
kids/elderly/hardcore. Возраст и иные числа сохраняются отдельно с единицами.
Конфликтующие числа сохраняются оба: валидный JSON не означает выполнимые правила.
Неизвестные win/loss/скорость/размеры нельзя дополнять собственными значениями.

input_status — ручная оценка всего ввода: valid, invalid, off_topic,
needs_clarification, unsafe_instruction. EXPLICIT здесь означает оценку наблюдаемого
текста по этим правилам, не утверждение о текущем ответе API. Противоречия требуют
уточнения; цитируемая надпись не становится командой. Injection не исполняется;
секреты, CSP и маршруты модели не меняются. Игровую часть можно размечать отдельно.

## Заморозка и независимость

FREEZE_COMMIT_SHA: `57d4b73e8965a60f0b69a20476f5057041535023`

Этот commit впервые фиксирует точные байты HELD-OUT. README добавлен следующим
коммитом, чтобы не создавать самоссылочный commit SHA. Хэш — SHA-256 исходных байтов
UTF-8/LF с завершающим newline, без JSON-канонизации. После фиксации HELD-OUT не менять
и не переформатировать; исправление требует отдельной версии набора и новой фиксации.

Контрольный файл находится в репозитории и уже виден автору NL-000: это разделение
по процедуре, не секретный blind benchmark. Будущая настройка использует DEV и
intent-corpus; HELD-OUT, его аннотации и результаты нельзя передавать настройщику,
включать в production prompts, fixtures или regression recipes. Перед финальным
сравнением заморозить код кандидата и параметры оценки. Сравнить baseline и кандидат
с одинаковыми маршрутами/настройками/заранее разрешёнными бюджетами и сохранить
исходные ответы и provenance. NL-000 такого бюджета не выдаёт.

При оценке отдельно считать точность признаков и соблюдение явных игровых требований;
UNKNOWN и конфликт не превращать в угаданные правильные ответы. Для игр фиксировать
реальные действия и наблюдаемый результат. Нет свидетельства — NOT_VERIFIED;
ошибку ставить только при наблюдаемом нарушении. Отделять synthetic, реальный LLM,
браузерную эмуляцию и физические устройства. Не подгонять код под контрольные ответы.
