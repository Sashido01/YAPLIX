## Данные и приоритет требований

[game-intent.ts](../src/game-intent.ts) возвращает исходную строку без trim или
перезаписи, жанр/аудиторию, объекты, действия, механики, числовые литералы,
фрагменты win/loss, управления, оформления и список исходных требований.
`idea` сохраняет весь замысел дословно, не заменяет его машинным пересказом.
Это ограниченные локальные подсказки по надёжным словам/конструкциям, а не
попытка полностью разобрать русский язык регулярными выражениями.

Каждая выделенная запись имеет `value`, `source`, `evidence`:

- EXPLICIT: дословное свидетельство в запросе, с нормализацией короткой метки.
- INFERRED: ограниченный вывод из названия знакомой игры или ясного контекста.
- DEFAULT: техническая политика продукта, явно отделённая от запроса.
- UNKNOWN: value/evidence null, нет уверенного вывода. Пустой список означает
  отсутствие извлечённых записей, а не пользовательский запрет этих объектов.

Возраст автора, родство «бабушка/мама», взрослые и подростки не заменяются
предполагаемыми kids/elderly/hardcore. Для названной змейки возможны INFERRED
движение, еда, рост; явные «без еды/роста» подавляют соответствующие подсказки.
Неизвестные сюжет, враги, жизни, количество предметов или пороги не добавляются.

Числа хранят исходный литерал и единицу, если она распознана. Не назначается
неизвестная роль вроде «возраст игрока» или «порог победы». Только безопасные
целые числа также имеют numeric value; дроби, экспоненты, большие числа и
словесные количества остаются с value null и точным литералом. Это не округление
и не подстановка другого числа. Последовательность правил сохранена в исходных
фрагментах; «сначала 5 рыбок, потом домой» не превращается в независимые цели.

[generation.ts](../src/generation.ts) формирует два сообщения: системный
контракт Full HTML и компактные пользовательские JSON-данные. Подробный Intent
остаётся внутри; `compactGameIntent` передаёт исходный `request` ровно один раз
и группы уверенных подсказок EXPLICIT / INFERRED. UNKNOWN, evidence, idea,
requirements, win/loss, numbers и повторы других фрагментов в LLM не передаются.
Явные правила, числа, запреты и последовательность действий остаются дословно
в `request`, а не копируются в несколько полей. Повторяющиеся метки механик
объединяются по приоритету EXPLICIT > INFERRED > DEFAULT.

В user остаётся только недостающее в system техническое требование: понятный
старт, реальный игровой цикл, уместный видимый прогресс без навязанного счёта.
HTML5/offline, управление, restart и ограничения безопасности уже есть в system
и повторно не отправляются. Дополнительные непустые suppliedSpec сохраняются
только при отличии от уже извлечённых подсказок; placeholder default/unknown/[]
и стандартный список keyboard/touch/pointer опускаются. Ответ модели по-прежнему
один полный HTML5; JSON — сериализация входа, не Blueprint и не формат ответа.

Начало, рабочее управление, реальный игровой цикл, уместный видимый прогресс,
перезапуск, touch/mobile и автономный HTML входят в DEFAULT. Счёт не навязывается
no-score игре; поражение и конечная победа не навязываются no-loss/endless игре.
Явные запреты, числа, порядок и правила выше inferred/default. Для edit передаются
полный существующий HTML, первоначальная идея и дословная правка; подсказки по
короткой правке не заменяют исходную игру.

## Конфликты и доверие

Обнаруженные простые несовместимости записываются с evidence: разные неуточнённые
пороги одного счёта, запрет прыжка с обязательным прыжком для победы, timed loss
при «без таймера», неясное сочетание пошаговости и real-time, запрещённое touch
или требуемые внешние ресурсы/сеть. Разные цели на явно разных уровнях и комбинация
жанров сами по себе не являются конфликтом. Arbitrary conflicts NOT_VERIFIED:
нет гарантии выявления любой сложной формулировки. Они остаются дословным входом
с системным запретом молча выбирать одну сторону.

Перед подготовкой сообщений узкая проверка отсекает ввод только из знаков и
алфавитные/клавиатурные/повторные последовательности, подкреплённые повтором
цифр или знаков: например, «абвгд 999 ???». Проверка не использует словарь
известных слов или жанров. UNKNOWN не ошибка; необычные идеи, сленг, короткие
названия, 2048 и emoji допускаются. Наличие содержательного слова или emoji
не позволяет объявить всю строку мусором по этому правилу. Пустота, превышение
500 символов и управляющие символы (кроме разрешённых whitespace) также
блокируются. Это не универсальная оценка осмысленности: сомнительный ввод
пропускается, если нет явных структурных признаков мусора.

При распознанном конфликте intent-режим останавливается до dispatch с
GAME_INTENT_CONFLICT. При невалидном/распознанном off-topic вводе — ошибка входа
(parseSpec либо GAME_INTENT_INPUT). Это внутренний экспериментальный режим;
новый UI уточнений и новая API-схема не добавлялись. Конфликты можно изучить
локально через gameIntent, изменить/уточнить исходный запрос и сравнить снова.

Host-инструкции считаются недоверенными данными. Некоторые явные команды
извлечь секрет, отключить CSP или выбрать платную модель блокируются локально.
Этот короткий список не универсальный injection-detector. Системное сообщение
не собирается из пользовательского текста; роли остаются system/user даже при
вставке XML-подобных тегов. Текст в кавычках не исполняется и не становится
host-командой. Настоящая граница безопасности остаётся в системном контракте,
существующем валидаторе и opaque sandbox; ни один из них здесь не ослаблен.
