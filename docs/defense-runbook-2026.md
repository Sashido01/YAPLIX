1. Проверить, что запущена **актуальная интегрированная копия YAPLIX**, а не устаревший backend на другом порту; сверить health/instance/build.
2. Выбрать настроенную модель. Не выдавать provider GET/preflight за доказательство будущего inference.
3. Проверить доступность сохранённой LIVE-игры из библиотеки.
4. Пройти Start → движение → Pause/Resume → Restart; открыть экспорт.
5. Подготовить автономный файл **из действительно созданной LLM-игры** как резерв для нестабильной сети.
6. Убедиться, что после чистой установки нет DEMO-gallery и пользовательских фиктивных записей.
7. Открыть презентацию и GitHub на нужных страницах.
8. Не показывать на общем экране `.env`, SQLite, токены, приватные трассы или персональные игровые HTML с секретами.

## На вопросы жюри

**«Это шаблоны?»** Нет: production создаёт HTML-код через LLM, preloaded DEMO удалены. Тестовые fixtures существуют только в тестах.

**«Что, если модель ошиблась?»** Проверка HTML/Canvas и bounded same-provider repair. Результат с доказанным критическим дефектом не должен сохраняться как готовый.

**«WebView?»** Формат автономного HTML подходит для встраивания; нативную проверку Android/iOS WebView у текущего кандидата не заявлять.

**«Как обеспечивается безопасность?»** Исполнение в opaque sandboxed iframe с CSP, без `allow-same-origin`; приватные данные и LLM-ключи остаются у backend.

**«Что с качеством?»** Есть реальные create/edit и воспроизводимые тесты. Победа для последней LIVE-игры и окончательная полная матрица после тестовой правки пока не подтверждены.
