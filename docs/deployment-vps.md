# Будущий VPS: архитектура, не развёртывание

План после локальной демонстрации. VPS, домен, HTTPS proxy и платные услуги
в MICRO-028N.2 не настраиваются и не покупаются.

Будущая цепочка: телефон → публичный домен/HTTPS → Nginx **или** Caddy →
loopback Node.js backend на Linux VPS → постоянное серверное хранилище.
Systemd service запускает backend при старте ОС, перезапускает после сбоя,
задаёт рабочий каталог, отдельного системного пользователя и ограничения ресурсов.
Версия Node должна соответствовать `package.json`; обновления проверяются на staging.

- Домен и TLS-сертификат управляются reverse proxy. Наружу открыты только
  необходимые HTTP/HTTPS порты; SSH ограничивается доверенными адресами/ключами.
  Node, SQLite и LLM endpoint не публикуются напрямую.
- SQLite хранится на постоянном диске, не в ephemeral build-каталоге. Один
  backend владеет файлами/worker lease. Согласованные backup через штатный
  механизм сохраняются отдельно; восстановление проверяется на копии, включая
  schema/integrity/FK и возврат к предыдущему deploy. WAL нельзя копировать
  как несогласованный отдельный файл. Миграция на другую БД — отдельное решение.
- LLM вызывается только сервером. Credentials находятся в защищённом файле
  окружения/systemd credentials, исключены из Git, HTML, QR, frontend и логов.
  Действующая allowlist провайдеров и FREE ONLY политика сохраняются;
  кредиты/планы автоматически не покупаются.
- Публичный QR должен вести на HTTPS-адрес **ограниченного player**, а не
  раскрывать owner dashboard, библиотеку или API генерации. Текущий `/phone`
  специально ограничен private IPv4/HTTP и не является готовым public endpoint.
  Замена его URL публичным доменом не создаёт безопасную публичную версию.

До многопользовательского запуска нужны отдельные решения и проверки:
идентификация пользователей, изоляция владельцев/библиотек/версий/jobs,
scoped read-only capabilities для выбранной игры, TTL/revoke/session policy,
CSRF/Origin/Host и trusted-proxy границы, rate limits/квоты, backups/diagnostics ACL,
управление секретами, аудит без токенов и устойчивость к злоупотреблению генерацией.
Текущая общая локальная библиотека, локальный owner и Telegram single-owner
не доказывают multitenancy. Общий ключ не заменяет разделение пользователей.

Opaque sandbox и CSP игры сохраняются. Перед публикацией проверить HTTPS,
доступ извне, запрет owner API, чужих версий и файлов, отзыв capability,
лимиты нагрузки/диска/очередей, backup/restore и обновление/rollback.
Выпуск требует отдельного разрешения и FULL на точном release SHA;
локальная Wi-Fi демонстрация не является production/public security PASS.
