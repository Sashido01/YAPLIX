# ChatGPT в YAPLIX — MICRO-029 Stage A1

ChatGPT — третий **ручной** провайдер создания и изменения HTML5-игр.
Ollama Cloud остаётся исходным выбором, OpenRouter Free — отдельным ручным
маршрутом. Auto означает Ollama и никогда не выбирает ChatGPT.

## Подключение личного аккаунта

1. Соберите проект: `npm run build`. Запустите локальный сервер: `npm start`.
2. Откройте `http://127.0.0.1:3000` (либо настроенный PORT). Нужны
   `YAPLIX_MODE=local` и `YAPLIX_HOST=127.0.0.1`, без PUBLIC_URL.
3. В разделе создания нажмите **Подключить ChatGPT**. Только это действие
   открывает системный браузер для SIWC. Дождитесь статуса «Подключён».
4. Вручную выберите **ChatGPT · GPT-6.1 Sol Medium**, введите идею и нажмите
   **Создать игру**. Для изменения выберите его в редакторе и создайте версию.
   Полный текущий HTML передаётся через прежний `generationMessages()`.
5. Для отключения нажмите **Отключить ChatGPT** в разделе создания.
   Игры, история и задания сохраняются. Активные HTTP-запросы отменяются;
   уже отправленный запрос всё равно считается израсходованной попыткой.

Ollama/OpenRouter keys для ручного ChatGPT не нужны. Их отсутствие не переводит
Auto на ChatGPT. `LIVE_PROVIDER` не меняется; `LIVE_PROVIDER=none` явно отключает
генератор. Сохранённый выбор ChatGPT не восстанавливается после reload:
нужен новый ручной выбор, без автоматического создания заданий.

## Длительная генерация — Stage A1.5

Только явно выбранный `providerMode=chatgpt` в durable live job получает
**45 минут на один inference response** и **60 минут на всё задание**.
Остаток после ответа доступен для локальной browser validation и сохранения;
сама browser validation сохраняет собственные короткие лимиты. Экспорт готовой
версии выполняется отдельно. Очередь входит в durable deadline. Restart сохраняет
исходный deadline, а не выдаёт новый час; уже созданные задания не продлеваются.
Continue выдаёт новый локальный бюджет только подтверждённому полному checkpoint,
без нового inference POST.

Общие `LLM_TIMEOUT_MS`, `LLM_REQUEST_TIMEOUT_MS`, `LLM_MAX_DURATION_MS` продолжают
управлять обычными маршрутами и сохраняют прежние ограничения конфигурации.
Фиксированные бюджеты ChatGPT от них отделены. `src/server.ts` передаёт обычную
конфигурацию без увеличения; worker и engine выбирают специальный бюджет по job.
Синхронные endpoints по-прежнему не могут вызывать ChatGPT. Входящие HTTP
headers/request timeouts сервера ограничивают загрузку API-запроса, а не время
фонового задания: создание job возвращает ответ сразу.

Один HTTP-диспетчер обслуживает только ChatGPT inference, включая body/SSE.
Ожидание заголовков и пауза между байтами ограничены 45 минутами; абсолютный
таймер ограничивает весь ответ теми же 45 минутами даже при keepalive-байтах.
Подключение/TLS остаётся ограничено 10 секундами. Применяется существующий
выбор direct/proxy через `YAPLIX_LLM_NETWORK`, `YAPLIX_LLM_PROXY`, proxy/NO_PROXY
переменные; автоматического direct fallback нет. Глобальные dispatcher и TLS
не изменяются. После успеха, ошибки или отмены таймер и dispatcher освобождаются.
OAuth, standalone probe, models GET и их короткие лимиты не расширяются.

Панель заданий показывает фактическое прошедшее время в минутах и секундах,
без процента готовности. Закрытие вкладки прекращает UI polling, но сохраняет
работу durable job на запущенном сервере. Кнопка отмены и отключение ChatGPT
прерывают ожидание; потраченная попытка не восстанавливается.

Offline-регрессии: `node --test tests/chatgpt-long.test.ts tests/chatgpt.test.ts`.
Они используют управляемые часы и синтетический Responses/SSE. Подтверждение
45-минутного реального upstream ожидания требует отдельного разрешённого LIVE-теста.

## Доступ и хранение

Личная сессия доступна только локальному владельцу на loopback. В LAN, HTTPS,
Telegram и listener для телефона сервер запрещает её использование. Подключение
и отключение требуют точного Origin и заголовка `X-Yaplix-ChatGPT: owner`.
Worker повторно проверяет режим и действующую авторизацию перед POST.

`LocalSiwc` сохраняет только существующие несекретные метаданные в
`.local/siwc-feasibility/host.json` и `registration.json`: host/client ID,
issuer и проверенный subject. Эти данные не возвращаются status API.
`authorization.lock` относится к standalone CLI, содержит только `pending` и
не удаляется автоматически после crash. Сервер использует блокировку OAuth
в памяти процесса: параллельный Connect запрещён, аварийный restart не оставляет
блокирующего файла. Сервер не читает и не удаляет locks CLI.

Access/refresh/ID tokens, authorization code, PKCE verifier и Authorization
не записываются в SQLite, trace, backup, экспорт или JSON API. Сырой SSE не
сохраняется. Токены находятся только в памяти серверного процесса. CLI OAuth
не авторизует сервер. Перезапуск, shutdown и отключение уничтожают сессию;
автоматического входа или refresh нет. Закрытие окна входа без callback
завершается ошибкой по ограниченному ожиданию (до 180 секунд); отключение
отменяет ожидание сразу. Повторный параллельный вход отклоняется.

## Responses и бюджет

Фиксированный контракт: `https://api.openai.com/v1/responses`,
`model: gpt-6.1-sol`, `reasoning: {effort: medium}`, `store: false`,
`stream: true`. Модель из SSE должна быть подтверждена и совпасть точно.
Общий parser сохраняет строгую проверку probe `YAPLIX READY`, а production
transport извлекает полный текст с существующим лимитом HTML 200000 байт.
События описаны в [официальной документации Responses](https://developers.openai.com/api/reference/resources/responses/streaming-events).
API key и платёжная конфигурация для SIWC здесь не добавляются.

Каждый новый ChatGPT job разрешает **максимум один inference POST**.
Перед внешней отправкой worker сохраняет `attempts=1` и provenance в SQLite
под действующей worker lease. При ошибке записи отправка не происходит.
Потеря процесса после резервирования считается возможным израсходованием:
restart, retry, Continue и повтор того же idempotencyKey второй POST не разрешают.
Автоматических fallback, retry и LLM repair нет, включая 429 и сетевые ошибки.
Старые синхронные endpoints не имеют durable-бюджета и ChatGPT не вызывают.

При ошибке задание получает `needs_attention`, исходная идея сохраняется.
Новый запрос после ошибки требует нового явного действия и нового задания.
Подключение OAuth позднее не запускает заблокированные задания. Полный
checkpoint с подтверждённой моделью разрешено заново проверить и сохранить
локально через Continue без обращения к модели, даже после отключения OAuth.
Неполный/неподтверждённый ответ не используется как проверенный checkpoint.

401/403 очищают авторизацию, 429 означает ограничение провайдера. Отсутствующая
или неверная модель, refusal, incomplete, пустой output, разрыв stream,
превышение размера и timeout не дают успешного результата. Ошибка браузерной
проверки или SQLite не вызывает новый inference. Результат проходит прежние
HTML/CSP/browser проверки; промпт, direct/intent и классификатор не изменяются.

## Границы проверки

A1 проверяется **offline**: подписанный синтетический OAuth, loopback callback,
mock Responses/SSE и отдельные проверки настоящим браузером. Это не является
реальным ChatGPT end-to-end PASS, проверкой физических телефонов или hosted CI.
Первый LIVE experiment требует отдельного разрешения владельца с точным
бюджетом OAuth, model GET и inference POST. A1 не запускает его автоматически.

Техническая доступность SIWC не доказывает право предоставления сервиса.
Пригодность личной подписки для коммерческого или многопользовательского
доступа не подтверждена. Доступность и квоты зависят от аккаунта и провайдера;
бесплатная или неограниченная генерация не обещается.

Для контрольного запуска в обычном PowerShell владельца:

```powershell
Set-Location D:\YAPLIX
npm run check
```

Если полный browser gate ограничен средой, результат A1 — PARTIAL, даже при
успешных unit и targeted browser. При отдельной проверке теста UI:

```powershell
node scripts/browser-tests.mjs test tests/jobs.spec.ts --project=chromium-desktop --project=chromium-320 --project=webkit-390 -g 'ChatGPT A1'
```
