# Подготовка к очной защите — Ubuntu 24.04

**Дата защиты по объявлению:** 20 ноября 2026. **Система ноутбука:** Ubuntu 24.04 LTS. Этот документ — план проверок, а не заявление о готовности приложения.

## Подготовка YAPLIX по кейсу Билайна

- [ ] Уточнить правила защиты, допустимые технологии, интернет, формат материалов и ограничение времени выступления.
- [ ] Утвердить демонстрируемый пользовательский сценарий с проверяемым результатом.
- [ ] Уложить реальный сценарий «промпт → сгенерированный код → игра с полноценным циклом» в 3–5 минут.
- [ ] Проверить HTML5-игру в WebView и игровой процесс без серверных зависимостей, отдельно от сетевой генерации LLM.
- [ ] Описать требования к оборудованию: CPU, RAM, GPU, свободное место, порты и периферия, если потребуются.
- [ ] Зафиксировать точные версии приложения, зависимостей и демоданных; описать загрузку без ручных правок исходников.
- [ ] Подготовить разрешённые к показу демоданные без персональной/закрытой информации.

## Репетиция на реальном ноутбуке

- [ ] На Ubuntu 24.04 выполнить установку/запуск строго по README или отдельному `docs/setup-ubuntu.md` (если такой будет создан).
- [ ] Запустить тесты приложения и smoke-тест основного пользовательского сценария.
- [ ] Проверить работу после перезагрузки ноутбука, включая повторный запуск и очистку состояния.
- [ ] Проверить HDMI/USB-C/переходник, разрешение внешнего экрана, масштабирование, читаемость текста и курсора.
- [ ] Проверить питание/зарядку, режим сна, отключение уведомлений и громкость.
- [ ] Отрепетировать действия с клавиатурой и мышью, открыть все необходимые файлы локально.
- [ ] Провести репетицию **без сети**; если сервис требует интернет, явно отметить зависимость и подготовить допустимый резервный сценарий.
- [ ] Оценить реальное время запуска и выступления на ноутбуке. Не придумывать результаты до измерения.

## Сбой внешней инфраструктуры

- [ ] При невозможности доступа к внешним API/LLM подготовить **отдельно обозначенный** демонстрационный режим или заранее записанный реальный сценарий; не выдавать имитацию за живое взаимодействие.
- [ ] Сохранить локальную копию презентации, скриншоты и запись работающего продукта, если правила мероприятия разрешают.
- [ ] Подготовить письменный план перезапуска и восстановления после ошибки.

## Перед выходом на защиту

- [ ] Зафиксировать Git SHA/тег показываемой версии и проверить `git status`.
- [ ] Убедиться, что ноутбук запускает именно эту версию, а не случайную рабочую ветку.
- [ ] Проверить сеть, зарядку, подключение дисплея и основной сценарий непосредственно на месте.
