# ADR 0002 — Базовая автоматизация репозитория до выбора кейса

**Статус:** принято, реализация подготовлена; результаты GitHub Actions проверяются после публикации.

**Актуализация TASK-001, 12 октября 2026:** репозиторий YAPLIX теперь Private, кейс Билайна назначен, стек приложения ещё не выбран. Существующие jobs и SHA Actions сохранены. repository-checks расширен на Ubuntu 24.04 и Windows; добавлены тесты hook и регистра путей. Сканер получает только дополнительное чтение PR, комментарии/summary/артефакты отключены; Gitleaks закреплён на 8.24.3 (прежняя версия по умолчанию Action). Полная история загружается, но PR/push сканируют диапазон изменений, ручной запуск — историю checkout. CI новой ветки требует публикации. Серверное применение ruleset ограничено тарифом; действуют [локальные hooks и командный регламент](../github-ruleset.md).

## Исторический контекст (до назначения кейса)

Команда из трёх участников пока не получила техническое задание. Неизвестны язык программирования, способ развёртывания и критерии тестирования продукта. Репозиторий публичный, поэтому важно минимизировать случайные публикации секретов и обеспечить воспроизводимую проверку документации.

## Решение

- Минимальный workflow GitHub Actions на `pull_request`, `push` в `main` и `workflow_dispatch`.
- `repository-checks` запускает скрипт только на стандартной библиотеке Python и его unit-тесты.
- `secret-scan` использует Gitleaks Action v3 по полной Git-истории.
- Внешние Actions закреплены полными SHA, Dependabot следит за их обновлениями.
- `GITHUB_TOKEN` имеет `contents: read`; сканер дополнительно `pull-requests: read`. Автоматическая запись в репозиторий не используется.
- Правила ветки добавляются отдельно, через интерфейс GitHub, **после** проверки CI.

## Последствия и ограничения

- Проверки не подтверждают работоспособность будущего приложения.
- Нельзя считать успешный запуск полной гарантией отсутствия секретов, юридических ограничений или уязвимостей.
- Для реального продукта потребуется отдельный CI/CD и тесты выбранного стека.
- Любые новые проверки должны быть документированы и проверены перед включением в обязательные условия слияния.
