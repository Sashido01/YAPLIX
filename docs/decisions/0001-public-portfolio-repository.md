# ADR-0001: Публичный командный репозиторий как инженерное портфолио

- **Дата:** 2026-10-09
- **Статус:** историческое решение; часть о публичности заменена TASK-001 (12 октября 2026)

## Актуализация TASK-001

Проект называется YAPLIX, репозиторий `Sashido01/yaplix` закрыт (Private). Назначен кейс Билайна — генерация браузерных игр по текстовому промпту. Историю первоначальной подготовки сохраняем; работа идёт через отдельные ветки, review и CI по [CONTRIBUTING.md](../../CONTRIBUTING.md). Публичное портфолио остаётся возможным будущим направлением после проверки прав. Стек ещё не выбран.

## Контекст

Три участника готовятся к региональному кейс-чемпионату «ИТ-спринт». Точный кейс и стек пока неизвестны. Владелец хочет, чтобы проект можно было предъявить потенциальному работодателю и чтобы участники могли совместно разрабатывать решение.

## Решение

- На момент принятия: вести общий публичный репозиторий с временным названием.
- Использовать `main` как основную ветку; изменения обсуждать через Issues и Pull Requests по мере необходимости.
- Фиксировать документацию, решения, тесты и вклад без вымышленных результатов.
- Не добавлять открытую лицензию и материалы кейса, пока не выяснены права и правила публикации.
- Локальную папку выбирает участник; она не является условием запуска.

## Последствия и риски

- Публичная история помогает оценить стиль разработки, но также делает код видимым другим командам.
- Любые конфиденциальные данные могут оказаться раскрыты навсегда, даже если удалить файл позднее.
- Окончательное имя продукта, структура приложения и технологический стек будут определены после получения кейса.
- Для командных решений потребуется согласование с остальными участниками.
