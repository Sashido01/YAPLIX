# Частная сеть: первый запуск, QR и Arena

Запускайте существующий `YAPLIX.cmd` или `npm run app`. Установщик не нужен.
Главное окно остаётся на loopback. Сервер автоматически выполняет **read-only**
диагностику; блок **Частная сеть · QR и Arena** показывает результат и предлагает
настройку. Одиночная игра, библиотека и генерация не требуют настройки Firewall.
Настройка доступна только владельцу через `http://127.0.0.1:PORT`, не телефону,
Arena-участнику, Telegram или публичному серверу.

## Что означает статус

- **READY**: прочитанная локальная конфигурация Windows покрывает выбранные порты
  и Node.js без обнаруженного применимого Block. Это **не** проверка с телефона.
- **ACTION_REQUIRED**: нужен выбор адаптера/Private-профиля, разрешение портов или
  устранение конфликта владельцем/администратором. Один Allow не отменяет Block.
- **UNVERIFIED**: ОС, доступ к NetSecurity, политика, маска, лимит/таймаут или
  неизвестные ограничения не позволяют сделать вывод. Не считать порты открытыми.

Показываются фактический `process.execPath`, активные физические адаптеры,
IPv4/маска и профиль, настроенные TCP-порты, listener/bind/PID и собственные
правила. Проверяются ActiveStore, фильтры программ/портов/адресов/интерфейсов,
ограничения Allow и эффективное разрешение локальных входящих правил. GPO/MDM,
запрещающие исключения или local merge, и применимый Block дают
`unable_to_manage`. Чужие правила и политики не исправляются. Ограниченный
Allow не становится доказательством READY. Сторонний Firewall, роутер, VPN и
достижимость другого устройства не могут быть доказаны этим снимком Windows.

Перед включением и выдачей QR диагностика повторяется. Известный Public/Domain
профиль не допускается. Если чтение политики недоступно, UI показывает
UNVERIFIED; ручное проверенное подключение остаётся возможным, автоматическое
изменение правил недоступно. Никакого скрытого переключения профиля нет.

## Настройка с согласия владельца

1. Подключите компьютер к доверенной Wi-Fi или Ethernet сети. Телефоны должны
   быть в достижимой локальной сети; на телефонах нужен только браузер.
2. Откройте **Частная сеть** и выберите физический адаптер. Если Windows считает
   его Public, самостоятельно проверьте сеть в **Параметры → Сеть и Интернет**.
   Меняйте профиль на Private только если доверяете этой сети. YAPLIX этого не делает.
3. Нажмите **Настроить доступ в частной сети**. Просмотрите точные имена правил,
   программу, адаптер, подсеть, порты и список удаляемых собственных правил.
4. Поставьте флажок согласия и нажмите **Применить с UAC**. Повышается только
   ограниченный PowerShell helper, основное приложение остаётся обычным процессом.
   Отказ от плана, отмена UAC и отсутствие прав не запрещают одиночную игру.
5. Дождитесь результата и повторной диагностики. При изменении сети/политики
   во время просмотра получите новый план. План одноразовый, срок — 5 минут.
6. Запустите **На телефон** или **Общий рейтинг**. Существующие listener'ы
   проверяют фактический bind и локальный HTTP GET. Затем **откройте QR на
   физическом телефоне**: только это проверяет его маршрут. Создание QR или GET
   с компьютера само по себе не является физической приёмкой.

Helper создаёт только PersistentStore **Inbound Allow TCP**, **Private**, для
точного пути текущего Node.js, выбранного физического адаптера и двух фактических
портов: `YAPLIX_PHONE_PORT` (по умолчанию **52604**) и `YAPLIX_ARENA_PORT`
(**52605**). Не назначайте обоим listener один порт. LocalAddress и RemoteAddress
ограничены **конкретной IPv4-подсетью выбранного адаптера**, например
`192.168.10.0/24`; это уже, чем общий Windows keyword `LocalSubnet` для всех сетей.
Правила для Public, Any address/interface/program/port и разрешение EdgeTraversal
не создаются. Нет изменения Defender, Firewall service, VPN, маршрутов или роутера.
Узкий scope описан параметрами [New-NetFirewallRule](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule).

## DHCP, обновления и удаление

LocalAddress ограничен подсетью, а не сегодняшним IP: DHCP внутри той же подсети
не требует нового Firewall-правила. Для нового QR обновите адрес listener.
Компромисс: правило покрывает адреса этой подсети на **том же адаптере**, только
для данного Node/портов/Private. Смена подсети/маски, адаптера, его имени, Node.js
или портов обнаруживается повторной проверкой. Новый точный план показывает
добавление замены и удаление устаревших собственных правил; без согласия ничего
не расширяется и не удаляется. Перезапуск не применяет план автоматически.

Имена собственных правил: `YAPLIX-LAN-<installation>-<configuration>`, группа
`YAPLIX LAN <installation>`. ID зависит от абсолютного пути этой копии проекта;
не переносите папку в ожидании автоматического удаления старой группы.
Ручные `YAPLIX demo hotspot TCP 52604`, `YAPLIX phone TCP 52604` и
`YAPLIX Arena TCP 52605` остаются нетронутыми. Подходящие ручные разрешения
учитываются, дубликаты не создаются. Совпадение имени с чужим правилом или
неподдерживаемое ручное изменение собственного правила требует ручного разбора.

**Удалить правила YAPLIX этой копии** показывает отдельный план и требует нового
согласия/UAC. Можно также открыть `wf.msc`, найти точную группу, сверить программу,
порты и описание и удалить только выбранные собственные правила вручную.
Закрытие комнаты/приложения **не** удаляет постоянные правила. Обновление кода
через git также их не меняет. Для полного отката сначала удалите свои правила
через UI текущей копии, затем откатывайте код. `.env`, SQLite и рекорды не меняются.

При ошибке helper пытается восстановить прежние собственные правила, проверяет
восстановление, затем убирает новые. `failed_rolled_back` означает проверенный
откат операций helper, `failed_rollback_incomplete` требует проверки в `wf.msc`:
Windows CIM/внешний администратор/аварийное завершение не дают транзакционной
гарантии. При неполном восстановлении новое ограниченное разрешение сохраняется.
Неизвестный исход helper не является PASS; повторите диагностику, не расширяйте
scope вслепую. Временные планы находятся в ignored `.local/lan-setup`, штатно
удаляются после ответа; оставшийся после аварии план не исполняется при запуске.

## Если телефон не открывает страницу

Сверьте текущую сеть и адрес QR; компьютер не должен спать. Проверьте listener
на нужном адресе/порту, Private-профиль, применимые Allow **и Block**, корпоративную
политику. Гостевая Wi-Fi/client isolation могут запрещать связь даже через один
роутер. Проверьте доступ VPN к LAN, мобильные данные телефона и правила маршрутизатора.
Не отключайте защиту целиком. Не открывайте порт в Интернет и не включайте проброс
портов. Достижимая LAN может содержать разные совместимые устройства; это не
обещание работы из другой сети. Публичный HTTPS/tunnel/VPS — отдельная будущая задача.

На Linux Windows helper не запускается и `ufw` не меняется. При необходимости
администратор вручную разрешает только inbound TCP выбранных портов на выбранном
интерфейсе от доверенной подсети по правилам своего дистрибутива, затем проверяет
подключение с телефона. Пример только для администратора с UFW: `sudo ufw allow
in on <interface> from <trusted-subnet> to <host-ip> port <port> proto tcp` —
сначала подставьте проверенные значения и проверьте `sudo ufw status verbose`.
Не включайте/сбрасывайте Firewall по этой инструкции автоматически.

## Проверки и границы доказательств

`node --test tests/lan-setup.test.ts` проверяет API/policy/consent и Windows helper
на подменённых NetSecurity cmdlets; реальные правила **не изменяются**.
`node scripts/browser-tests.mjs test tests/lan-setup.spec.ts` проверяет UI с
синтетическими ответами Windows, включая отказ/Public/UAC cancel. Это не тест UAC
и не сетевой тест телефона. Чистый clone: сначала `npm ci`, `npm run build` и
установка браузеров по [development setup](development-setup.md).
